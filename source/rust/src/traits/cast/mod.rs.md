# `rust/src/traits/cast/mod.rs`

## Scope and assumptions

- **Scope:** The non-deprecated `InfCast<usize> for f64` implementation generated by `impl_inf_cast_int_float`, as required by the `get_rounding_distance<T, 2>(k, size)` L2 sensitivity allowance. This is not an audit of arbitrary integer/float casts or all other implementations of `InfCast`.
- **Invariant:** For any 64-bit `usize` value `n` for which `f64::inf_cast(n)` returns `Ok(y)`, the finite float `y` is at least the exact integer `n`. An erroneous downward cast near `2^53` could shrink the Gaussian L2 stability allowance and undercount privacy loss.
- **Assumptions:** `FBig<Up>::from(IBig::from(n))` rounds upward at the bignum arithmetic layer, and `f64::from_fbig` preserves that directed mode. Those Rust/dashu implementations were not compiled or dynamically verified in this session. Source revision: `ef1a238634d6196b01a1a1e77d3d5ad2340e3094`.

## Analysis

### Source inspection

The generic `impl_inf_cast_int_float` macro implements the `usize -> f64` directed cast and returns `f64::from_fbig(FBig::<Up>::from(IBig::from(n)))`. It does **not** use an ordinary nearest `n as f64` cast. `InfCast` specifies an upper bound or error. The `InfSqrt` function then uses this result as its input.

The [independent reference model](../../../../../tools/tests/test_directed_gaussian_rounding_model.py) constructs the mathematically smallest binary64 not less than `n`, using `math.nextafter` and exact `Fraction.from_float` comparisons. It checked 9,484 integer values spanning `0..5000`, edges of powers of two, perfect squares, and 4,000 seeded 64-bit values, including `2^53+1` and `2^64-1`. Every modeled cast was an upper bound; this checks an independent **specification model**, not the actual Rust `FBig` or native cast.

For `n=2^53+1`, upward binary64 conversion is `2^53+2`, not nearest `2^53`. For `n=2^64-1`, it is `2^64`. The latter is still a finite binary64 and is sufficient for the subsequent square root.

**Result:** Source wiring is consistent with directed upward rounding; no undercount was identified. **Partial** because the backend and actual compiled behavior were not independently proved.
