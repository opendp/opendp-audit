# Polars array.get(false) passes an infallibility gate despite data-dependent OOB errors

## Invariant, scope and security relevance

A stable grouped query or contribution-truncation plan must not allow a fallible expression to fail as a function of protected records. `check_infallible` is the common syntactic gate for aggregation expressions in `make_stable_group_by` and `truncate_domain`. This review is limited to `FunctionExpr::ArrayExpr(ArrayFunction::Get(bool))`, not the full whitelist, all aggregation functions, or an end-to-end differential-privacy proof.

A public Array(Int64, 2) *literal* and private integer index produce success for index 0 but a Polars out-of-bounds error for index 2. The input domain contains only primitive integer columns and a public one-row bound, so both index cases have verified domain membership. **A native OpenDP private LazyFrame release now reproduces this data-dependent error status after construction with a finite advertised pure-DP cost.**

## Minimal native private-release witness

The [native Rust regression](../tools/integration/polars_array_get_private_release.rs) constructs a public domain with only two integer columns, `k: Int32` and `idx: Int64`, plus `Margin::select().with_max_length(1)`. Both one-row datasets with `k=0` and `idx=0` or `idx=2` pass the actual OpenDP `domain.member(...)` check. They are one record replacement apart, with symmetric distance **2**.

The query holds the array `[5,6]` in an **immutable public Array(Int64,2) literal**, not a private array column. It executes `group_by(k).agg(public_array.arr.get(col("idx"), false).first().alias("picked"))` and then selects a noisy bounded DP sum of `col("picked")`, clipped to public bounds `[0,10]` at positive noise scale 1. This dependency prevents the optimizer from pruning away the fallible lookup. The OpenDP constructor returns a measurement, and `measurement.map(&Bounds::from(2_u32))` returns a **finite** `MaxDivergence` cost.

At [compiled native OpenDP CI #45110800652](https://github.com/opendp/opendp-audit/actions/runs/45110800652) (pinned main, with `--features contrib,polars`), the `idx=0` invocation and `OnceFrame.collect()` succeed. For `idx=2`, `OnceFrame.collect()` returns `FailedFunction("ComputeError(ErrString(\"get index is out of bounds\"))")`. Thus the caller distinguishes otherwise admissible neighboring inputs by the presence of this *specific* error before considering noisy output. The same test with `null_on_oob=true` returns successful releases for both indices.

**Test-harness failure, not missing reproduction:** That CI run marked one of two Rust tests failed because the test checked `failure.to_string()` for the phrase "out of bounds", while OpenDP's error `Display` hides the nested message. The job log prints the exact nested error in its `Debug` representation. The test assertion was subsequently changed to `format!("{failure:?}")`; a clean CI rerun is required to remove this harness-only failure. The other native control test passed.

The event "the specific out-of-bounds error was returned" is impossible when the fixed public array is indexed at 0 and occurs when indexed at 2. For a publicly observable error status, this is incompatible with a **finite pure-DP** guarantee over these domain members at symmetric distance 2. This argument does not depend on the realized noisy sum. It does not characterize additional whitelist arms, production deployment configurations, or privacy loss from timing.

## Executed verification and disposition

**Actually executed:** A standalone Python standard-library [source model](../tools/tests/test_array_get_oob_whitelist_model.py) compared OpenDP's unconditional `Get(_)` acceptance with fallible `Get(false)` indexing across 20,672 deterministic boundary/random cases. The audit repository's local schema validator and 25 Python unit tests passed. Separately, the audit's [real Polars 1.36.1 runtime regression](../tools/integration/polars_array_get_runtime.py) ran **four compiled-Polars tests successfully** in [GitHub Actions run #45108716569](https://github.com/opendp/opendp-audit/actions/runs/45108716569). Those tests exercise grouped fixed-size array indexing with a column-valued index. In the same successful run, the [compiled native OpenDP constructor regression](../tools/integration/polars_array_get_open_dp.rs) confirmed that the stable group-by constructor **accepts** the fallible `ArrayFunction::Get(false)` expression on pinned main `ef1a238634d6196b01a1a1e77d3d5ad2340e3094` and **rejects** it on unmerged PR #3155 head `63a32139856e16b7d415766e6a9becc25aa748e1`. The pinned main/PR Rust job and the four Polars tests all completed successfully in [CI #45108716569](https://github.com/opendp/opendp-audit/actions/runs/45108716569). This also confirms the stable-constructor admission and backend behavior; the end-to-end OpenDP private-release error is separately reproduced above.

**Additional source inspected:** OpenDP and Polars source and Polars' checked-in `test_array_get` tests. Both the OpenDP constructor comparison and the grouped Polars runtime behavior were subsequently executed natively, as described above. An initial targeted issue/PR search missed [upstream PR #3155](https://github.com/opendp/opendp/pull/3155) because its title refers broadly to stable group-by hardening. Its reviewed, **unmerged** head `63a32139856e16b7d415766e6a9becc25aa748e1` removes `check_infallible` and replaces it with a restrictive `check_permutation_invariance` traversal that rejects `ArrayFunction` variants not explicitly allowed. This is a proposed fix, not a fix on upstream main.

**Finding:** [Audit issue #71](https://github.com/opendp/opendp-audit/issues/71) (labeled `privacy`) was closed after discovery of the open fix PR. Verification is now **Reproduced for the OpenDP private-release error channel**, its constructor-admission defect, and the pinned Polars OOB behavior. The privacy impact is demonstrable for a caller who observes the specific OOB error on the two in-domain inputs and finite advertised MaxDivergence map at symmetric distance 2. CI #45110800652 failed solely on error-message formatting in the test assertion, as documented in the native witness. Upstream disposition: **Pending PR** [#3155](https://github.com/opendp/opendp/pull/3155), not merged or fixed on the pinned main SHA. This is separate from the earlier [group-by influence-bound audit](polars-groupby-influence-bound.md), which explicitly assumed total aggregation expressions and excluded the whitelist.
